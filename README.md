# stabplayer

手持摄像机视频的**实时去抖播放器**,面向 4K、画质优先。播放时实时估计相机运动并平滑,输出始终是**完整画面**(不裁切、不放大),
去抖把画面移开后露出的边缘缺口用前后相邻帧补上。只依赖 OpenGL 3.3,与显卡厂商无关。

## 特性

- 实时去抖:整幅相似变换(平移 + 旋转 + 缩放),5 档强度预设,运行中按键切换,可与原片对比或左右分屏
- 输出完整画面,按输出分辨率等比缩放(4K 屏 1:1,2560 宽约 2/3,1920 宽 1/2);`1` 键进入 1:1 原生像素
- 画质:去抖变换、缩放、YUV→RGB 在一个 GPU 着色器里一次完成(只有一次重采样);放大/1:1 用 Catmull-Rom 双三次,
  缩小用 mip + 锐度补偿;支持 8-bit / 10-bit;暗部加 ±0.5 LSB 静态抖动避免色带
- 开播前缓冲最多 10 秒内容,供前瞻平滑;音频时钟为主,音频设备停摆时自动退回系统时钟
- 默认把资源用满,只守一条内存底线(给系统留至少 2GB 或总内存的 25%)
- 每次运行写 `stabplayer.log`(环境、显卡、音频、逐秒帧率/丢帧/耗时、事件、异常栈),方便远程排查

## 环境

- 实测环境:Windows 10 + NVIDIA 驱动(原生 OpenGL 3.3)+ Python 3.12。开发时也在 WSL2(Python 3.10,Mesa D3D12)里跑通。
- **AMD / Intel 核显没有实测**(只用到 OpenGL 3.3 的通用功能,理论上可用)。
- 4K 30fps 在上述环境实测:约 4 核 CPU,GPU 绘制约 2ms;帧缓冲 10 秒约 3.7GB 内存,补缺口纹理池约 410MB 显存。

## 运行(源码)

```
pip install -r requirements.txt
python stabplayer.py 视频文件            # 不带参数则弹出选文件框
```

命令行选项见 `python stabplayer.py --help`,常用的有 `--preset 1~5`、`--mode stab|orig|split`、`--no-fill`、`--size 1600x900`、
`--fullscreen`、`--mute`、`--prebuffer 秒`、`--buffer-gb GB`、`--list-audio`、`--selftest`。

## 打包成 Windows 免安装目录

```
pip install -r requirements-build.txt
build.bat                                # 输出 dist\stabplayer\ (含 README.txt、selftest.bat)
```

发布时要把**整个** `dist\stabplayer` 文件夹(含 `_internal`)一起发,只发 exe 不行。exe 没有数字签名,SmartScreen 或杀毒软件可能提示。
`release/` 里是随包发布的用户说明和自检脚本,`build.bat` 打包后会自动拷进去。

## 去抖强度预设

| 预设 | σ(平滑核) | 校正范围 |
|---|---|---|
| 1 light | 0.15s | 1.04 |
| 2 standard | 0.25s | 1.06 |
| 3 strong | 0.40s | 1.10 |
| **4 stronger(默认)** | 0.60s | 1.15 |
| 5 max | 1.00s | 1.25 |

「校正范围」是允许的最大校正量(≈ 画面宽 × (1−1/倍数)/2 像素),画面本身不裁切。σ 超过 1s 没有收益,上限由校正范围决定。

## 实现概览

```
stabplayer.py   播放器: 解码流水线(PyAV)、OpenGL 渲染、音频(SDL)、界面、日志、自检
stabcore.py     去抖算法(只依赖 numpy / OpenCV): 运动估计、相机路径、稳定器、矩阵
stabres.py      内存 / 线程优先级等资源小工具(只依赖标准库)
```

数据流:解码线程(有界队列)→ 降采样亮度做运动估计 → 累积相机路径 → 稳定器给出每帧校正量 → 主线程把 YUV 平面直传 GPU,
一个着色器完成变换 + 缩放 + 补缺口 + YUV→RGB。

- **运动估计**(`MotionEstimator`):降采样(默认宽 960)灰度图,半分辨率网格取角点,双向 LK 光流,覆盖度加权 RANSAC 拟合相似变换
  (网格取点 + 低绝对阈值,避免被前景大运动物体带偏)。
- **稳定器**(`Stabilizer`):带前瞻的高斯加权局部二次回归平滑(不会磨平真实摇镜);强/弱两条平滑按增益 β 在校正范围内插值,
  β 先做最小值滤波再高斯平滑,避免逐帧起伏产生高频伪影。
- **补缺口**:每帧最多 6 个相邻帧(±4/±8/±16 帧)放在 GPU 纹理数组池里;着色器按「底色=边缘延伸 → 远到近叠相邻帧 → 最后叠当前帧」
  做级联羽化,权重只在帧边缘落在输出画面内的那一侧渐变,无缺口的一侧像素保持原样。
- **时钟**:音频位置相对系统时钟低通(τ=0.5s)后作为主时钟;设备 1 秒不取数据则退回系统时钟。音频用 ctypes 直调 SDL2
  (`pygame._sdl2.audio` 的 pause/close 持有 GIL,会与 SDL 音频线程互等死锁)。
- **高分屏**:Windows 上启动时声明 DPI 感知(`enable_dpi_awareness()`),否则缩放 125% 等设置下画面会被系统二次缩放而变糊。
  自己写脚本直接构造 `Player` 时要先调用它。

## 验证工具(`tools/`)

都是命令行脚本,用法见各文件开头的说明;视频路径作为参数,仓库里不带测试视频。

| 脚本 | 用途 | 环境 |
|---|---|---|
| `check_render.py` | GPU 输出与 numpy/OpenCV 参考逐像素对比:色彩、变换与符号、缩小(mip)、1:1;有阈值,不通过退出码为 1 | 需要 OpenGL |
| `check_fill.py` | 补缺口的 GPU 输出对 CPU 参考;`--identity` 检查无缺口时最外圈像素不被混入邻帧;`--out` 存标注图供目视 | 需要 OpenGL |
| `check_fill_geometry.py` | 相邻帧映射矩阵的几何校验(正确映射应明显优于各种错误对照) | 仅 CPU |
| `eval_residual.py` | 逐时间段比较「原始 vs 各档预设」的残余抖动,参照量取画面中无前景运动的区域 | 仅 CPU |
| `play_scripted.py` | 脚本驱动真实播放器(按键、截图、暂停、跳转),检查媒体时钟确实在推进 | 窗口 + 可选音频 |
| `check_ui.py` | 全屏快捷键(F / F11 / Alt+Enter / 双击 / Esc)、输入法是否被关闭、鼠标移动是否扰乱播放节奏 | 真实显示器;窗口会全屏几秒 |
| `check_audio.py` | 音频死锁压力测试(持有 GIL 的计算 + 高频 pause/play/start/switch) | 音频输出设备;会播放声音 |

改着色器后先跑 `check_render.py` 和 `check_fill.py`;改 `stabcore.py` 的几何后跑 `check_fill_geometry.py`;
改音频或窗口/输入处理后分别跑 `check_audio.py`、`check_ui.py`。

## 已知限制

- 只做整幅相似变换,不处理果冻效应和镜头畸变;画面缺少纹理或大面积运动物体占主导时运动估计会失效
  (估计失败的帧按「相机没动」处理,去抖效果减弱,不会乱动画面)。
- 补出的缺口来自其他时刻的帧:静态背景处无缝;缺口处有快速运动的物体或亮度剧变(如镜头扫向暗处)时,
  补出的窄带与主画面之间可能有可见接缝。四角极少数像素用边缘延伸兜底。
- HDR 视频不做色调映射;只测过 8-bit / 10-bit 4:2:0(其他格式先转成 4:2:0)。
- 未实测:AMD / Intel 核显、真实 4K 屏(用超出屏幕的 3840×2160 窗口验证过)、4K60。
